# 회차별 정원 자동 마감 + 설문 이탈 방지 (Apps Script)

구글 폼 → 스프레드시트로 응답이 쌓이는 **기존 방식을 그대로 두고**, 회차별 정원이 차면
폼에서 해당 시간대를 자동으로 없애고 초과 접수를 자동 취소 처리합니다.
체험 후 설문을 안 하고 가는 이탈을 잡기 위한 운영 화면용 집계도 함께 제공합니다.

## 2026.9.19 학산마당극 놀래 기준

| | 컬러링 체험 | 바인더 체험 |
|---|---|---|
| 참가비 | 무료 | 30,000원 (현장 결제) · 완성품 판매 20,000원 |
| 회차 | 30분 × 11타임 (13:00~18:30, 쉬는 시간 없음) | 동일 |
| 회차당 정원 | **6명** | **5명** |
| 하루 정원 | **60명** (수채화지 60장) | **50명** (체험용 바인더 50개) |

회차 수(11) × 정원(6·5) = 66명·55명이지만 **재료가 상한**입니다. `dayLimit` 으로 막아서
60명·50명이 차면 남은 회차도 자동으로 마감됩니다.

> 주최 측이 안내한 체험시간은 15:00~18:30(17:00~17:30 휴식)이지만, 그 시간만으로는
> 6타임(36명·30명)뿐이라 목표 인원을 채울 수 없습니다. 13:00부터 쉬는 시간 없이
> 운영하는 기준으로 맞춰져 있습니다.

두 프로그램이 **같은 10개 타임을 공유하되 정원은 별개**입니다.
그래서 슬롯 키가 `프로그램|시간`입니다.

## 회차표는 사이트가 기준을 들고 있다

`index.html` · `index_en.html` · `reserve.html` 는 회차표를 직접 들고 있습니다.

```js
const SLOT_TIMES = ['13:00','13:30','14:00','14:30','15:00','15:30',
                    '16:00','16:30','17:00','17:30','18:00'];   // 30분 11타임
```

API 응답 중 **프로그램 구분이 있고 이 표 안에 있는 회차**만 잔여 인원으로 인정합니다.
조건에 맞는 항목이 하나도 없으면 "예약 서버 점검 중" 안내를 띄우고 접수를 막습니다.

> 배포가 밀린 구버전 스크립트가 지난 행사의 회차표(11:00~19:40 · 20분 간격)와
> 그때의 예약 건수를 내려주면, 사이트에는 없는 시간대가 뜨고 지난 행사 예약이
> 이번 행사의 **마감**으로 표시됩니다. 위 규칙은 그 상황을 화면에서 끊기 위한 것입니다.
> **근본 해결은 아래 재배포**입니다. 운영 시간을 바꿀 때는 `CONFIG.START_TIME` /
> `END_TIME` / `INTERVAL_MIN` 과 세 HTML 의 `SLOT_TIMES` 를 **함께** 고쳐야 합니다.

## 어디까지 자동으로 막히나

| 상황 | 동작 |
|---|---|
| 정원이 찬 뒤 폼을 **새로 여는** 사람 | 해당 시간대가 선택지에서 **사라짐** |
| 웹페이지에서 예약 버튼을 누르는 사람 | 잔여 재확인 후 **마감이면 폼이 열리지 않음** |
| 폼을 **미리 열어두고** 나중에 제출 | 제출은 되지만 **"정원초과 자동취소"** 표시 + 행 강조 + 담당자 메일 |
| 동시 제출 | `LockService`로 순차 처리 |
| 전 회차 마감 | 폼 자체가 닫힘 |

> **한계**: 구글 폼에는 선택지별 정원 기능이 없어, 제출 자체를 100% 사전 차단하는 것은 불가능합니다.
> **선택지 제거(사전) + 제출 후 자동 취소(사후)** 두 겹으로 처리하며,
> 사후 취소된 분께는 담당자가 안내해 주셔야 합니다.
>
> 프로그램이 둘이라 시간 선택지는 **두 프로그램 모두 마감된 시간**만 지울 수 있습니다.
> 폼을 `컬러링 13:30` 처럼 **한 문항으로 합치면** 사전 차단이 정확해집니다.

## 설문 이탈 방지

체험 설문은 무료 체험의 참여 조건이자 결과보고 증빙(목표 60건)이라, 이탈하면 성과가 그대로 깎입니다.
시스템으로 할 수 있는 부분과 현장 운영으로 막아야 하는 부분이 나뉩니다.

**현장 운영 (효과가 가장 큼)**
1. **작품을 설문 완료 후에 전달** — 완성작을 바로 주지 말고, 설문 제출 완료 화면을 보여주시면
   엽서 봉투에 담아 전달. "정가 25,000원을 무료로 드리는 조건"이라 명분도 분명합니다.
2. **건조 시간을 설문 시간으로** — 수채화는 마르는 시간이 필요합니다. 채색이 끝난 5분이
   자리에 앉은 채 설문을 쓰게 만드는 유일한 타이밍입니다. 나가는 길에 QR을 찾게 하면 이미 늦습니다.
3. **테이블마다 QR 스탠드** — 부스 입구가 아니라 **앉은 자리**에 둡니다.
4. **예비 태블릿 1대** — 휴대폰이 없거나 QR이 어려운 어르신·어린이 동반 참가자용.
5. **설문은 1분 안에** — 만족도·가격 적정성·재구매 의사·흥미도·연령·거주지 6문항 이내로.

**시스템**
6. **설문 링크에 회차 자동 입력** — 사이트에서 예약하면 브라우저에 회차가 저장되고,
   설문 버튼을 누를 때 프로그램·시간이 프리필됩니다. 참가자가 적지 않아도 회차별 집계가 됩니다.
   (`index.html`의 `SURVEY_ENTRY_PROGRAM` / `SURVEY_ENTRY_TIME`에 설문 폼 문항 ID를 넣어야 작동)
7. **운영 화면 `staff.html`** — 회차별 **예약 인원 대비 설문 응답 수**를 30초마다 갱신합니다.
   "14:30 컬러링 6명 중 1명 작성"이 보이면 아직 부스 근처에 계실 때 붙잡을 수 있습니다.
   목표 60건 진행률과 액자 잔여도 함께 표시됩니다.

## SNS 후기 → 액자 증정

```
SNS 후기 업로드 (#헬로미추 #수채화컬러링)
  → 후기 인증 설문에 게시물 링크 + 캡처 이미지 첨부
  → 운영자가 시트의 '확인' 칸에 체크
  → 액자 증정 (선착순 28명, 시간대와 무관한 전체 카운터)
```

- 인증 설문에는 **단답형(링크) + 파일 업로드(이미지)** 문항이 필요합니다.
- **파일 업로드 문항은 응답자의 구글 로그인이 필요합니다.** 현장에서 로그인이 안 되는 분이
  있으므로, 이미지 업로드는 **선택**으로 두고 링크만 필수로 받은 뒤 부스에서 화면을 확인하는
  운영을 권장합니다. 사이트에도 같은 안내를 넣어 두었습니다.
- 액자 잔여는 `확인` 칸에 값이 들어간 건수만큼 차감되어 사이트와 운영 화면에 표시됩니다.

## 설치

1. 응답이 쌓이는 **스프레드시트**를 열고 `확장 프로그램 → Apps Script`
2. 새 스크립트 파일을 만들고 `slot-capacity.gs` 내용을 붙여넣기
3. 맨 위 `CONFIG` 수정
   - `PROGRAMS` — 프로그램 키·회차당 정원·하루 정원 (컬러링 6/60 · 바인더 5/50)
   - `START_TIME` / `END_TIME` / `INTERVAL_MIN` — 13:00 / 18:00 / 30 (마지막 회차 시작이 18:00)
   - `COL_PROGRAM` / `COL_TIME` — 예약 시트 헤더에 들어 있는 글자 (부분 일치)
   - `SURVEY_SHEET_NAME` — 체험 설문 응답 시트 이름 (설문 진행률 집계용)
   - `SNS_SHEET_NAME` — 후기 인증 설문 응답 시트 이름 (액자 카운터용)
   - `NOTIFY_EMAIL` — 정원 초과 알림 받을 주소 (선택)
4. `setupTriggers` 실행 → 권한 승인
5. `debugAvailability` 실행 → 로그에서 슬롯 수·마감 회차·액자 잔여·설문 미작성 회차 확인

## 사이트와 연결

`index.html` / `staff.html` 은 `API_URL`에서 아래 형태를 기대합니다.

```json
{
  "slots": [ { "program": "컬러링", "time": "13:30", "capacity": 6, "remain": 4 } ],
  "sheetStock": [ { "key": "01 소서노", "remain": 12 } ],
  "goods": [ { "key": "액자", "remain": 21 } ],
  "surveyProgress": [ { "program": "컬러링", "time": "13:30", "booked": 6, "done": 4, "missing": 2 } ]
}
```

기존 `doGet` 안에서 아래 세 함수 결과를 넣으면 됩니다.

```js
function doGet() {
  const payload = {
    slots:          getSlotAvailability(),
    sheetStock:     getSheetStock(),        // 기존 도안 재고 로직 그대로
    goods:          getGoodsStock(),
    surveyProgress: getSurveyProgress()
  };
  return ContentService.createTextOutput(JSON.stringify(payload))
                       .setMimeType(ContentService.MimeType.JSON);
}
```

코드를 고친 뒤에는 `배포 → 배포 관리 → 편집 → 버전: 새 버전 → 배포`로 **재배포**해야
사이트에 반영됩니다. 배포 URL은 그대로 유지됩니다.

**저장만 하면 편집기에서만 동작합니다.** 실서비스 URL(`/exec`)은 마지막으로 *배포한 버전*을
계속 서빙하므로, 재배포하지 않으면 사이트는 지난 행사 설정 그대로 응답을 받습니다.
재배포가 끝났는지는 브라우저에서 `/exec` 를 열어 확인하는 게 가장 빠릅니다.

```json
{"slots":[{"program":"컬러링","date":"9월 19일 (토)","time":"13:00","capacity":6,"remain":6}, ...]}
```

- `program` 이 있고 `time` 이 `13:00`부터 30분 간격이면 최신 배포본입니다. (슬롯 22개 = 컬러링 11 + 바인더 11)
- `program` 이 없거나 `time` 이 20분 간격이면 **구버전이 서빙 중**입니다.
- 지난 행사 응답이 같은 시트에 남아 있으면 그대로 마감으로 잡히므로, 옛 행을 다른 탭으로
  옮기거나 `처리상태`에 `취소`를 넣어 제외하세요. 새 시트를 쓴다면 `CONFIG.SHEET_NAME` 지정.

## 붙여넣기 없이 배포하기 (clasp)

편집기에 복사·붙여넣기 하는 대신, 대표님 PC에서 명령 한 줄로 배포할 수 있습니다.
`update.sh` 가 최신 코드를 내려받아 올리고 새 버전으로 배포까지 합니다.

**최초 1회 설정**

```bash
npm i -g @google/clasp            # 설치 (맥에서 권한 오류면 sudo 를 앞에)
clasp login                       # 브라우저에서 구글 로그인 → 허용
```

그리고 **https://script.google.com/home/usersettings** 에서
`Google Apps Script API` 를 **사용** 으로 켭니다. (이걸 안 켜면 clasp 이 동작하지 않습니다)

```bash
mkdir ~/hm-script && cd ~/hm-script
clasp clone <스크립트 ID>          # ID: 편집기 → 프로젝트 설정(⚙️) → 스크립트 ID
clasp deployments                 # 배포 ID(AKfycb...) 확인 → update.sh 의 DEPLOY_ID 에 기입
curl -O https://raw.githubusercontent.com/Izzy-Lee/HM/main/apps-script/update.sh
chmod +x update.sh
```

**그 뒤로는 매번 이 한 줄**

```bash
cd ~/hm-script && ./update.sh
```

> 첫 실행 뒤에는 반드시 `/exec` 주소를 열어 응답을 확인하세요.
> 행사 당일에는 손대지 않는 것이 안전합니다.

## 점검

- `debugAvailability` — 마감 회차 / 액자 잔여 / 설문 미작성 회차를 로그로 출력
- `syncFormChoices` — 폼 선택지를 즉시 동기화
- 예약 시트 `처리상태` 칸에 `취소` 또는 `노쇼` 입력 → 그 자리는 다시 예약 가능
